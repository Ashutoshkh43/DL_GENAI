1. The big picture: how a neural network learns

In Week 1, we learned that a neural network consists of neurons, weights, biases, activation functions, and layers. We also saw how to create tensors and build a simple model in PyTorch.

Week 2 focuses on the learning process. A network starts with parameters that may be far from correct. It makes predictions, measures how wrong they are, calculates how its parameters should change, and updates those parameters repeatedly.

The complete learning cycle

  1. Input: Supply a batch of examples to the model.
  2. Forward pass: Calculate predictions from the current weights and biases.
  3. Loss calculation: Compare predictions with the correct targets.
  4. Backward pass: Calculate gradients that describe how the loss changes with each parameter.
  5. Optimizer step: Update parameters using those gradients.
  6. Repeat: Continue for multiple batches and epochs.
  7. Validation: Evaluate performance on data not used to update the parameters.
Important distinction: The forward pass makes predictions. The backward pass calculates gradients. The optimizer updates parameters. These are three separate operations.

Essential terminology

TermMeaning
ParameterA value learned by the model, such as a weight or bias.
Forward passComputing predictions from inputs and parameters.
TargetThe correct output associated with an input.
LossA numerical measure of prediction error.
GradientThe derivative of the loss with respect to a parameter.
Learning rateA factor controlling the size of a gradient-based update.

ValidationEvaluating a model on data that is not used for parameter updates.

2. Universal Approximation Theorem

2.1 What is the theorem?

The Universal Approximation Theorem describes the expressive power of neural networks. Under suitable conditions, a feedforward neural network with a hidden layer containing enough neurons and a suitable nonlinear activation function can approximate a continuous function on a compact domain as closely as desired.

In simpler words, a neural network can represent a wide variety of complicated input-output relationships, even when those relationships are not straight lines.

2.2 Why are hidden layers useful?

Consider a simple linear model:

\(y = wx+b\)

This model can represent a straight-line relationship between a single input and output. Many real-world relationships are more complicated: customer behaviour, image patterns, and interactions among variables may not follow a straight line.

Hidden layers allow a network to combine intermediate features. Nonlinear activation functions allow the network to represent nonlinear relationships.

2.3 Why does nonlinearity matter?

Suppose every layer performs only a linear transformation:

\(h_1=W_1x+b_1\)

\(h_2=W_2h_1+b_2\)

Substituting the first equation into the second gives:

\(h_2=W_2(W_1x+b_1)+b_2\)

\(h_2=(W_2W_1)x+(W_2b_1+b_2)\)

This is still a linear transformation followed by a bias. Stacking linear layers without nonlinear activations does not provide the same expressive power as a nonlinear network.

2.4 Common nonlinear activation functions

ActivationFormulaTypical behaviour
Sigmoid \(\sigma(x)=\frac{1}{1+e^{-x}}\) Maps values to the interval (0, 1).
Tanh \(\tanh(x)\) Maps values to the interval (-1, 1).
ReLU \(\max(0,x)\) Returns zero for negative inputs and the input itself for positive inputs.
Leaky ReLU \(\max(\alpha x,x)\) Allows a small negative output when the input is negative.

2.5 What the theorem does not guarantee

  • It does not guarantee that a small network will approximate every function well.
  • It does not guarantee that training will find the right parameters.
  • It does not guarantee good performance on unseen data.
  • It does not say that one particular architecture is best for every task.
  • It does not mean that every function can be represented exactly by a finite network.
GA concept: The theorem concerns what a network can approximate under suitable conditions. It is not a guarantee about how quickly, or whether, an optimization algorithm will learn that approximation.

3. Forward pass through a neural network

3.1 What happens during a forward pass?

The forward pass takes input data and passes it through the network layer by layer. Each layer performs a weighted sum, adds a bias, and may apply an activation function.

\(z=Wx+b\)

\(a=f(z)\)

Here:

  • \(x\) is the input vector.
  • \(W\) is the weight matrix.
  • \(b\) is the bias vector.
  • \(z\) is the result before activation.
  • \(f\) is the activation function.
  • \(a\) is the activation or output of that layer.

3.2 Calculating one neuron by hand

Suppose a neuron receives two inputs:

\(x_1=2,\quad x_2=3\)

Its weights and bias are:

\(w_1=0.5,\quad w_2=-1,\quad b=1\)

First calculate the weighted sum:

\(z=w_1x_1+w_2x_2+b\)

\(z=(0.5)(2)+(-1)(3)+1=-1\)

With ReLU activation:

\(a=\max(0,-1)=0\)

The neuron's output is therefore zero. Notice that the bias is included before the activation function.

3.3 Forward pass through two layers

Suppose a network has one input, two hidden neurons, and one output neuron. Use the following parameters:

  • Input: \(x=2\)
  • Hidden weights: \(w_1=1,\ w_2=-1\)
  • Hidden biases: \(b_1=0,\ b_2=1\)
  • Hidden activation: ReLU
  • Output weights: \(v_1=2,\ v_2=3\)
  • Output bias: \(c=1\)

First hidden neuron:

\(z_1=(1)(2)+0=2\)

\(h_1=\operatorname{ReLU}(2)=2\)

Second hidden neuron:

\(z_2=(-1)(2)+1=-1\)

\(h_2=\operatorname{ReLU}(-1)=0\)

Output neuron, assuming a linear output:

\(y=(2)(h_1)+(3)(h_2)+1\)

\(y=(2)(2)+(3)(0)+1=5\)

The final output is 5. If the output layer instead used a sigmoid, the value before sigmoid would still be 5, but the final output would be \(\sigma(5)\), approximately 0.993.

3.4 Matrix form

When a layer has many neurons, matrix multiplication performs all weighted sums efficiently.

\(z=Wx+b\)

If the input has 4 features and the layer has 3 neurons, then \(x\) has shape \((4,)\), \(W\) can have shape \((3,4)\), and \(b\) has shape \((3,)\). The resulting \(z\) has shape \((3,)\).

With a batch of 8 examples, the input often has shape \((8,4)\). In PyTorch, a linear layer with 4 input features and 3 output features uses weights of shape \((3,4)\) and produces an output of shape \((8,3)\).

3.5 A forward pass in PyTorch

import torch
import torch.nn as nn

model = nn.Sequential(
    nn.Linear(4, 8),
    nn.ReLU(),
    nn.Linear(8, 3)
)

x = torch.randn(5, 4)
output = model(x)

print(output.shape)  # torch.Size([5, 3])

Here, the model receives five examples, each containing four features, and produces three output values per example.

Exam tip: For a forward-pass numerical question, calculate one layer at a time. Do not apply the next layer until you have calculated the previous layer's activation.

4. Loss functions

4.1 What is a loss function?

A loss function measures how different a model's prediction is from the target. Training uses the loss to determine whether parameter updates are improving the model.

A loss is a numerical value. A smaller loss usually indicates predictions that better match the targets according to that particular loss function. The best loss depends on the task.

4.2 Mean Squared Error (MSE)

Mean Squared Error is commonly used for regression, where the goal is to predict a numerical value.

\(\operatorname{MSE}=\frac{1}{N}\sum_{i=1}^{N}(y_i-\hat y_i)^2\)

The error for each example is squared, and the squared errors are averaged. Squaring makes large errors contribute more heavily.

Worked example

Suppose the targets are \([3,5]\) and predictions are \([2,7]\).

\(\operatorname{MSE}=\frac{(3-2)^2+(5-7)^2}{2}\)

\(=\frac{1+4}{2}=2.5\)

The MSE is 2.5.

criterion = nn.MSELoss()
loss = criterion(predictions, targets)

4.3 Binary cross-entropy (BCE)

Binary cross-entropy is used for binary classification, such as predicting whether a customer will leave a service.

Let \(y\) be the binary target and \(p\) be the predicted probability of class 1. The binary cross-entropy for one example is:

\(-[y\log(p)+(1-y)\log(1-p)]\)

If the target is 1, the expression reduces to \(-\log(p)\). Predicting a probability close to 1 gives a small loss; predicting a probability close to 0 gives a large loss.

If the target is 0, the expression reduces to \(-\log(1-p)\). The loss is small when the predicted probability is close to 0. 

# Model returns logits (not sigmoid probabilities)
criterion = nn.BCEWithLogitsLoss()
logits = model(x)
loss = criterion(logits, targets.float())

BCEWithLogitsLoss combines sigmoid and binary cross-entropy in a numerically stable operation. When using this loss, the model should normally return logits rather than applying a sigmoid inside the model.

4.4 Categorical cross-entropy

For a mutually exclusive multiclass classification task, such as classifying an image into one of ten categories, a common choice is categorical cross-entropy.

\(L=-\sum_{k=1}^{C}y_k\log(p_k)\)

Here \(C\) is the number of classes, \(y_k\) is the target indicator for class \(k\), and \(p_k\) is the predicted probability for that class. With one-hot targets, only the correct class contributes to the sum.

In PyTorch, nn.CrossEntropyLoss normally receives unnormalized class scores called logits. It combines the log-softmax operation and negative log-likelihood loss. 

criterion = nn.CrossEntropyLoss()
logits = model(images)  # [batch_size, number_of_classes]
loss = criterion(logits, labels)  # integer class indices

For a batch of images with 10 possible classes, the logits generally have shape \((B,10)\), while the class-index labels generally have shape \((B,)\).

4.5 Which loss should you choose?

TaskTypical lossCommon target format
RegressionMSENumerical values
Binary classificationBCE or BCE with logits0/1 values

Common mistake: Do not confuse the final predicted class with the values passed to a loss function. For CrossEntropyLoss, pass logits, not argmax class indices or already-softmaxed probabilities.

5. Gradient descent

5.1 What is a gradient?

A gradient describes how a function changes with respect to its input parameters. For a model with many parameters, the gradient contains a derivative for every parameter.

If the loss is \(L\) and a parameter is \(w\), then \(\frac{\partial L}{\partial w}\) describes the local rate of change in loss as \(w\) changes.

  • A positive gradient means increasing the parameter slightly would increase the loss locally.
  • A negative gradient means increasing the parameter slightly would decrease the loss locally.
  • A gradient close to zero means the loss changes very little locally in that direction.

5.2 The gradient descent update rule

\(w_{\text{new}}=w_{\text{old}}-\eta\frac{\partial L}{\partial w}\)

Here:

  • \(w_{\text{old}}\) is the current parameter.
  • \(\eta\) is the learning rate.
  • \(\frac{\partial L}{\partial w}\) is the gradient of the loss with respect to the parameter.

The minus sign means the update moves in the direction opposite to the gradient, which is the local direction of steepest decrease for a differentiable loss.

5.3 Numerical example

Suppose:

\(w_{\text{old}}=2,\quad \eta=0.1,\quad \frac{\partial L}{\partial w}=4\)

Then:

\(w_{\text{new}}=2-(0.1)(4)=1.6\)

The updated weight is 1.6. The positive gradient causes the parameter to decrease in this step.

5.4 What happens when the learning rate changes?

Learning ratePossible effect
Too smallTraining may progress very slowly.
ReasonableUpdates may make useful progress toward lower loss.
Too largeUpdates may overshoot, oscillate, or diverge.

A larger learning rate does not automatically mean a better model. The best value depends on the model, data, loss surface, and optimizer.

5.5 Batch, stochastic, and mini-batch gradient descent

MethodHow examples are usedPractical characteristic
Batch gradient descent Uses the entire training dataset for one gradient calculation. Can be expensive for large datasets.
Stochastic gradient descent Uses one example per update. Frequent, noisy updates.
Mini-batch gradient descent Uses a small batch of examples per update. Common in deep learning; balances computational efficiency and update frequency.

If a dataset contains 1,000 examples and the batch size is 100, one epoch normally consists of 10 mini-batches, assuming all examples are used and the last batch is full.

5.6 Optimizers in PyTorch

optimizer = torch.optim.SGD(model.parameters(), lr=0.01)

optimizer.zero_grad()  # Clear previous gradients
predictions = model(x)  # Forward pass
loss = criterion(predictions, targets)
loss.backward()  # Calculate gradients
optimizer.step()  # Update parameters

PyTorch optimizers implement the parameter update rules. SGD is a common gradient-based optimizer; Adam is another widely used optimizer that adapts updates using running estimates of gradients and squared gradients.

Order matters: Calculate the loss, call backward() to compute gradients, and then call step() to update the parameters. Clear old gradients before accumulating the next batch's gradients.

Question: A weight is 0.8, the learning rate is 0.05, and its gradient is -2. What is the new weight after one standard gradient descent update?

\(w_{\text{new}}=0.8-(0.05)(-2)=0.8+0.1=0.9\). Answer: 0.9.

6. Customer churn prediction with a neural network

6.1 What is customer churn?

Customer churn occurs when a customer stops using a service or leaves a business. A churn prediction model estimates the likelihood that a customer will leave, based on information such as usage, tenure, subscription type, and billing information.

If the target indicates whether a customer churned, the task is typically a binary classification problem.

6.2 Understand the dataset

A tabular churn dataset may contain:

  • Numerical features: tenure, monthly charges, number of support calls.
  • Categorical features: contract type, payment method, service plan.
  • Target: whether the customer churned, often encoded as 0 or 1.

The exact columns and preprocessing steps depend on the dataset used in the lecture. The following is a general workflow, not a claim about a particular course dataset.

6.3 Data preprocessing

  1. Load the dataset and inspect its columns, data types, and missing values.
  2. Separate input features from the target.
  3. Encode categorical features into numerical representations.
  4. Handle missing values according to a consistent policy.
  5. Scale numerical features when appropriate.
  6. Split the data into training and validation sets.
  7. Convert processed features and targets to suitable tensor types.

A neural network operates on numerical tensors. Text categories such as "monthly" and "annual" cannot be passed directly into an ordinary linear layer without encoding.

6.4 Why feature scaling can help

Suppose one feature represents customer tenure between 0 and 10, while another represents annual charges between 0 and 100,000. Their numerical scales differ considerably.

Scaling can make optimization easier by preventing some numerical features from dominating simply because of their units. A common standardization is:

\(x_{\text{scaled}}=\frac{x-\mu}{\sigma}\)

Estimate scaling statistics from the training data and apply those same statistics to the validation data. Using validation data to fit preprocessing parameters can leak information into model development.

6.5 Package imports

import numpy as np

These packages support data manipulation, tensor operations, neural network construction, mini-batch loading, dataset splitting, and feature scaling. Exact imports depend on the implementation.

6.6 Define a neural network

Suppose the processed dataset contains \(d\) input features. A simple model can map those features to a hidden representation and then produce one output logit. 

class ChurnMLP(nn.Module):
    def __init__(self, input_dim):
        super().__init__()

        self.network = nn.Sequential(
            nn.Linear(input_dim, 32),
            nn.ReLU(),
            nn.Linear(32, 16),
            nn.ReLU(),
            nn.Linear(16, 1)
        )

    def forward(self, x):
        return self.network(x)

The hidden layers learn intermediate combinations of the input features. The final layer produces one logit for each example. A sigmoid can convert that logit into a probability when needed.

6.7 Weight initialization

Training typically starts with initialized weights and biases. If every neuron in the same layer begins with identical weights, the neurons can receive identical gradients and fail to learn different features.

Randomized initialization helps break this symmetry. The initialization method should also be appropriate for the activation function and network architecture.

  • Xavier/Glorot initialization: Often used with activations such as tanh, with variants depending on the layer.
  • Kaiming/He initialization: Designed with ReLU-like activations in mind.
  • Bias initialization: Often begins at zero, although some models use other choices.
model = ChurnMLP(input_dim)

for layer in model.modules():
    if isinstance(layer, nn.Linear):
        nn.init.kaiming_uniform_(
            layer.weight,
            nonlinearity="relu"
        )
        nn.init.zeros_(layer.bias)

This example applies Kaiming initialization to all linear layers. For a final output layer, other initialization choices may also be appropriate. Initialization is not the same as the later gradient-based learning process.

6.8 Training and validation setup

The training set is used to calculate gradients and update parameters. The validation set is used to monitor how well the current model performs on held-out examples. 

train_dataset = TensorDataset(X_train, y_train)
val_dataset = TensorDataset(X_val, y_val)

train_loader = DataLoader(
    train_dataset,
    batch_size=64,
    shuffle=True
)

val_loader = DataLoader(
    val_dataset,
    batch_size=64,
    shuffle=False
)

Shuffling the training examples helps avoid relying on a fixed order of examples. Validation data is usually not shuffled because its order does not need to be randomized for evaluation.

6.9 Training loop

model = ChurnMLP(X_train.shape[1])
criterion = nn.BCEWithLogitsLoss()
optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.001
)

for epoch in range(20):
    model.train()
    total_loss = 0.0

    for features, targets in train_loader:
        targets = targets.float().view(-1, 1)

        optimizer.zero_grad()

        logits = model(features)
        loss = criterion(logits, targets)

        loss.backward()
        optimizer.step()

        total_loss += loss.item() * features.size(0)

    average_loss = total_loss / len(train_loader.dataset)
    print(f"Epoch {epoch + 1}: loss = {average_loss:.4f}")

This example assumes that the feature tensors and target tensors have already been prepared with compatible shapes and types. The targets are converted to floating-point values with shape \((B,1)\) to match the output logits.

6.10 Model training versus validation

The model should be put into training mode during training and evaluation mode during validation. These modes affect layers such as dropout and batch normalization when present. 

model.train()  # Training mode
# Forward pass, loss, backward pass, optimizer update

model.eval()   # Evaluation mode
with torch.no_grad():
    # Forward pass and evaluation only
    pass

model.eval() does not disable gradients by itself. torch.no_grad() prevents gradient tracking in the enclosed computation. These are separate operations.

6.11 Converting logits to churn predictions

For a binary classifier, sigmoid converts a logit \(z\) into a probability:

\(p=\frac{1}{1+e^{-z}}\)

A threshold such as 0.5 can be used to produce a binary prediction: classify as class 1 when \(p\geq0.5\). The threshold can be changed depending on the cost of false positives and false negatives. 

probabilities = torch.sigmoid(logits)
predictions = (probabilities >= 0.5).int()

7. Backpropagation

7.1 What is backpropagation?

Backpropagation is an efficient method for computing derivatives of a loss with respect to the parameters of a neural network. It applies the chain rule from the output of the network back through the preceding computations.

The forward pass calculates intermediate values. Backpropagation uses those values to calculate gradients. An optimizer then uses the gradients to update the parameters.

Backpropagation calculates gradients; it does not, by itself, update the weights. The optimizer performs the update.

7.2 The chain rule

If \(y=f(u)\) and \(u=g(x)\), then \(y=f(g(x))\). The chain rule gives:

\(\frac{dy}{dx}=\frac{dy}{du}\frac{du}{dx}\)

The derivative of the outer function is multiplied by the derivative of the inner function. This principle allows us to calculate gradients through multiple connected operations.

7.3 Backpropagation through a simple scalar chain

Consider the computation:

\(x=2,\quad a=3x,\quad y=a^2\)

First calculate the forward values:

\(a=3(2)=6,\quad y=6^2=36\)

Now calculate the derivatives:

\(\frac{dy}{da}=2a=12\)

\(\frac{da}{dx}=3\)

Apply the chain rule:

\(\frac{dy}{dx}=\frac{dy}{da}\frac{da}{dx}=12(3)=36\)

The derivative of the final output with respect to \(x\) is 36.

7.4 A second scalar example involving loss

Suppose a model predicts:

\(\hat y=wx,\quad L=\frac{1}{2}(\hat y-y)^2\)

To calculate the gradient with respect to \(w\), apply the chain rule:

\(\frac{\partial L}{\partial w} =\frac{\partial L}{\partial\hat y} \frac{\partial\hat y}{\partial w}\)

\(\frac{\partial L}{\partial\hat y}=\hat y-y\)

\(\frac{\partial\hat y}{\partial w}=x\)

Therefore:

\(\frac{\partial L}{\partial w}=(\hat y-y)x\)

If \(x=2\), \(w=3\), and \(y=4\), then \(\hat y=6\), so:

\(\frac{\partial L}{\partial w}=(6-4)(2)=4\)

7.5 Backpropagation through an MLP

A multilayer perceptron (MLP) consists of connected layers. During the forward pass, each layer's output becomes the next layer's input. During backpropagation, gradients flow in the reverse direction.

For a two-layer network:

\(z_1=W_1x+b_1,\quad a_1=f(z_1)\)

\(z_2=W_2a_1+b_2,\quad \hat y=g(z_2)\)

The loss depends on \(\hat y\). Backpropagation first calculates how the loss changes with respect to the output layer, then propagates that information through the hidden layer.

For example, the gradient with respect to the second layer's weights depends on the output-layer error and the hidden activations. The gradient with respect to the first layer's weights also depends on how the hidden activations affect the output.

7.6 Activation derivatives

Activation functions contribute derivatives to the chain rule. For ReLU, away from zero:

\(f'(z)= \begin{cases} 0,&z<0\\ 1,&z>0 \end{cases}\)

If a ReLU neuron has a negative pre-activation, its local derivative is zero. This can block gradient flow through that neuron for that input.

For sigmoid:

\(\sigma'(z)=\sigma(z)(1-\sigma(z))\)

The sigmoid derivative becomes small when its output is close to 0 or 1, which can contribute to vanishing gradients in deep networks.

7.7 Backpropagation in PyTorch

x = torch.tensor([2.0], requires_grad=True)

a = 3 * x
y = a ** 2

y.backward()

print(x.grad)  # tensor([36.])

Setting requires_grad=True allows PyTorch to track operations involving the tensor. Calling backward() computes the gradient of the scalar output with respect to tracked inputs.

In ordinary model training, parameters already have gradient tracking enabled. Their gradients can be accessed through parameter.grad after backpropagation.

By the chain rule, \(\frac{dy}{dx}=\frac{dy}{du}\frac{du}{dx}=3u^2(2)\). Since \(u=2(2)=4\), the derivative is \(3(16)(2)=96\). Answer: 96.

8. The XOR problem

8.1 What is XOR?

XOR stands for exclusive OR. For two binary inputs, the output is 1 when the inputs are different and 0 when they are the same.

\(x_1\)\(x_2\)\(x_1\operatorname{XOR}x_2\)
000
011
101
110

8.2 Why is XOR a problem for a single-layer model?

A single neuron with a linear decision boundary cannot separate the XOR examples into the correct two classes. The positive examples are \((0,1)\) and \((1,0)\), while the negative examples are \((0,0)\) and \((1,1)\).

No single straight line can place both positive examples on one side and both negative examples on the other. XOR is therefore not linearly separable.

Important: The limitation concerns a single linear decision boundary. A network with hidden neurons and nonlinear activations can combine intermediate representations to solve XOR.

8.3 How a hidden layer helps

A small network can create intermediate features that respond to different input combinations. A later layer combines those features to produce the XOR output.

One way to understand the idea is that hidden neurons can form separate decision regions. The output neuron then combines these regions. The key is that the network is no longer restricted to one linear decision boundary.

8.4 A threshold-unit illustration

For conceptual understanding, define a threshold unit that returns 1 when its input is greater than zero and 0 otherwise.

Consider two hidden units:

\(h_1=\operatorname{step}(x_1+x_2-0.5)\)

\(h_2=\operatorname{step}(x_1+x_2-1.5)\)

The first unit detects whether at least one input is 1. The second detects whether both inputs are 1.

Then the XOR result can be expressed as:

\(y=\operatorname{step}(h_1-2h_2-0.5)\)

Check the four input combinations:

\(x_1\)\(x_2\)\(h_1\)\(h_2\)Output
00000
01101
10101
11110

This is a threshold-unit illustration of the logic. A practical neural network trained using gradient descent commonly uses differentiable activations such as sigmoid or tanh instead of the hard step function.

8.5 Forward pass and backpropagation for XOR

The forward pass evaluates each hidden neuron, applies its activation, and then calculates the output. A loss function compares the output with the correct XOR label.

Backpropagation calculates how the loss changes with respect to the hidden and output weights. Gradient-based optimization adjusts those parameters across training steps.

With sigmoid activations, the forward calculation for each neuron follows:

\(z=Wx+b,\quad a=\sigma(z)\)

The output can then be compared with the target using a classification loss. The gradients propagate through the output layer and then the hidden layer.

Answer: B. The two positive examples cannot be separated from the two negative examples by one straight line. Hidden layers with nonlinear activations can solve this limitation.

9. Fashion MNIST classification: overview and data processing

9.1 What is Fashion MNIST?

Fashion MNIST is an image classification dataset containing grayscale images of fashion items. Each image is 28 by 28 pixels and belongs to one of ten classes.

The ten classes are:

  1. T-shirt/top
  2. Trouser
  3. Pullover
  4. Dress
  5. Coat
  6. Sandal
  7. Shirt
  8. Sneaker
  9. Bag
  10. Ankle boot

Unlike customer churn prediction, which usually uses tabular features, Fashion MNIST uses image pixels as input features.

9.2 Image representation

A grayscale image contains 28 × 28 = 784 pixel values. A simple MLP can flatten these pixel values into a vector of length 784.

\(28\times28=784\)

When using a batch of \(B\) images, the original image tensor typically has shape \((B,1,28,28)\), where the second dimension is the number of channels.

After flattening, the shape becomes \((B,784)\). Flattening changes the shape, not the number of pixel values in each image.

9.3 Download and transform the dataset

from torchvision import datasets, transforms
from torch.utils.data import DataLoader

transform = transforms.ToTensor()

train_dataset = datasets.FashionMNIST(
    root="./data",
    train=True,
    download=True,
    transform=transform
)

test_dataset = datasets.FashionMNIST(
    root="./data",
    train=False,
    download=True,
    transform=transform
)

train_loader = DataLoader(
    train_dataset,
    batch_size=64,
    shuffle=True
)

test_loader = DataLoader(
    test_dataset,
    batch_size=64,
    shuffle=False
)

transforms.ToTensor() converts a supported image into a tensor and scales its pixel values to the range [0, 1]. The precise preprocessing pipeline may vary depending on the course implementation.

9.4 Training, validation, and test sets

  • Training set: Used to learn model parameters.
  • Validation set: Used to monitor performance and guide model selection or hyperparameter tuning.
  • Test set: Used for a final evaluation after model choices have been made.

In a general workflow, part of the training data may be reserved for validation. The official test set should not be repeatedly used to tune the model, because doing so can make test performance less representative of generalization.

Fashion MNIST's test set is not automatically the same as a validation set. Use the exact split described by the course implementation when reproducing its results.

10. Fashion MNIST MLP implementation in PyTorch

10.1 Why use an MLP?

A multilayer perceptron treats each image as a vector of pixel values and learns combinations of those values. It is a useful model for understanding the complete classification pipeline.

An MLP does not explicitly preserve the two-dimensional spatial structure in the way a convolutional neural network does. Even so, it can learn a useful mapping from flattened pixels to class scores.

10.2 Define the network

import torch
import torch.nn as nn

class FashionMLP(nn.Module):
    def __init__(self):
        super().__init__()

        self.network = nn.Sequential(
            nn.Flatten(),
            nn.Linear(28 * 28, 256),
            nn.ReLU(),
            nn.Linear(256, 128),
            nn.ReLU(),
            nn.Linear(128, 10)
        )

    def forward(self, x):
        return self.network(x)

The first operation flattens each image. The first linear layer maps 784 input features to 256 hidden features, the second maps 256 to 128, and the final layer maps 128 features to ten class logits.

10.3 Understand the layer dimensions

LayerInput featuresOutput features
FlattenImage of 28 × 28 pixels784
Linear 1784256
Linear 2256128
Output linear layer12810

For a batch size of 64, the output shape of the final layer is \((64,10)\). Each row contains ten scores for one image.

10.4 Count the trainable parameters

A fully connected layer with \(n_{\text{in}}\) input features and \(n_{\text{out}}\) output features has:

\(\text{Parameters}=n_{\text{in}}n_{\text{out}}+n_{\text{out}}\)

The first term counts weights, and the second counts biases.

For the example model:

  • First layer: \(784(256)+256=200{,}960\)
  • Second layer: \(256(128)+128=32{,}896\)
  • Output layer: \(128(10)+10=1{,}290\)

Total trainable parameters:

\(200{,}960+32{,}896+1{,}290=235{,}146\)

This is the parameter count for the example architecture above, not a claim that every course implementation uses these exact hidden-layer sizes.

10.5 Why are there ten output units?

Fashion MNIST has ten classes, so the final layer produces ten class scores. A model can select the class with the highest score using argmax. 

model = FashionMLP()

images, labels = next(iter(train_loader))
logits = model(images)

print(images.shape)  # Typically [64, 1, 28, 28]
print(logits.shape)  # [64, 10]

predicted_classes = logits.argmax(dim=1)
print(predicted_classes.shape)  # [64]

The ten values are logits, not necessarily probabilities. When using CrossEntropyLoss, pass these logits directly into the loss function.

11. Fashion MNIST forward pass

11.1 Forward-pass pipeline

  1. Load a batch of images.
  2. Flatten each image from 28 × 28 pixels into 784 values.
  3. Apply the first linear transformation.
  4. Apply ReLU to introduce nonlinearity.
  5. Apply the next linear transformation and ReLU.
  6. Calculate ten output logits.
  7. Compare the logits with the true class labels using a loss function.

11.2 Understand logits and predictions

Suppose a model produces the logits:

\([1.2,\ -0.5,\ 0.8,\ 2.1,\ 0.1,\ -1.0,\ 0.4,\ 0.7,\ -0.2,\ 1.0]\)

The largest score is 2.1 at index 3. Using zero-based indexing, argmax predicts class 3, which corresponds to Dress in the standard Fashion MNIST class ordering.

The largest logit gives the predicted class even before applying softmax, because softmax preserves the ordering of the logits. However, the logit itself is not a probability.

11.3 Cross-entropy with logits

criterion = nn.CrossEntropyLoss()

logits = model(images)  # Shape: [batch_size, 10]
loss = criterion(logits, labels)

The labels are normally integer class indices with shape \((B,)\). Do not apply argmax before calculating the loss: doing so discards the information needed for differentiable training.

11.4 Calculate batch accuracy

predictions = logits.argmax(dim=1)
correct = (predictions == labels).sum().item()
accuracy = correct / labels.size(0)

If 52 out of 64 images are classified correctly, the batch accuracy is:

\(\frac{52}{64}\times100=81.25\%\)

For a complete dataset, aggregate the number of correct predictions and the number of examples across all batches. Do not simply average batch accuracies if the batches have different sizes.

12. Fashion MNIST training loop

12.1 The standard training-loop sequence

The training loop processes one batch at a time. Each batch produces predictions and a loss, then backpropagation calculates gradients and the optimizer updates the model.

  1. Set training mode.
  2. Fetch a batch of images and labels.
  3. Clear old gradients.
  4. Run the forward pass.
  5. Calculate the loss.
  6. Run the backward pass.
  7. Update model parameters.
  8. Accumulate metrics for the epoch.

12.2 Complete training-loop example

device = torch.device(
    "cuda" if torch.cuda.is_available() else "cpu"
)

model = FashionMLP().to(device)
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.001
)

num_epochs = 5

for epoch in range(num_epochs):
    model.train()

    running_loss = 0.0
    correct = 0
    total = 0

    for images, labels in train_loader:
        images = images.to(device)
        labels = labels.to(device)

        optimizer.zero_grad()

        logits = model(images)
        loss = criterion(logits, labels)

        loss.backward()
        optimizer.step()

        running_loss += loss.item() * images.size(0)

        predictions = logits.argmax(dim=1)
        correct += (predictions == labels).sum().item()
        total += labels.size(0)

    epoch_loss = running_loss / total
    epoch_accuracy = correct / total

    print(
        f"Epoch {epoch + 1}: "
        f"loss={epoch_loss:.4f}, "
        f"accuracy={epoch_accuracy:.4f}"
    )

This is a general example. It assumes the data loader returns tensors that can be moved to the selected device, and the model architecture is the one defined earlier.

12.3 Why multiply the batch loss by batch size?

Many PyTorch loss functions return a mean loss across the batch by default. To calculate an example-weighted average over the whole epoch, multiply each mean batch loss by its batch size, sum those values, and divide by the total number of examples.

\(\text{Epoch loss}= \frac{\sum_b \text{mean loss}_b\times n_b} {\sum_b n_b}\)

This matters if the last batch is smaller than the others.

12.4 What is an epoch?

One epoch is one pass through all training examples. If there are 600 examples and the batch size is 100, an epoch normally contains six batches.

Training for five epochs means that the model has processed the training set five times, although the order may change between epochs if the loader shuffles the examples.

12.5 Why do we shuffle the training data?

Shuffling changes the order in which examples appear during training. It helps avoid systematic patterns caused by the original ordering of the dataset and changes the composition of mini-batches across epochs.

12.6 Common training-loop mistakes

  • Forgetting optimizer.zero_grad() and unintentionally accumulating gradients.
  • Calling optimizer.step() before loss.backward().
  • Using a loss function that does not match the task or target format.
  • Moving the model to the GPU but leaving the input tensors on the CPU.
  • Using the wrong output or label shapes.
  • Reporting only the last batch's loss as the whole epoch's loss.
  • Forgetting to return the model to training mode after evaluation.
Memorize this order: zero_grad → forward → loss → backward → step.

Question 6 — Chain rule

If \(u=4x\) and \(y=u^2\), calculate \(\frac{dy}{dx}\) when \(x=3\).

Answer and reasoning

\(u=4(3)=12\). \(\frac{dy}{du}=2u=24\), and \(\frac{du}{dx}=4\). Therefore \(\frac{dy}{dx}=24(4)=96\). Answer: 96.

14. Fashion MNIST validation loop

14.1 Why validate?

Training loss tells us how well the model fits the training data. Validation metrics help estimate how well the model performs on held-out examples and can reveal overfitting.

A model can continue to improve on training examples while its performance on validation examples stops improving. Monitoring both helps guide decisions about model size, regularization, learning rate, and training duration.

14.2 Validation-loop example

model.eval()

val_loss_total = 0.0
correct = 0
total = 0

with torch.no_grad():
    for images, labels in val_loader:
        images = images.to(device)
        labels = labels.to(device)

        logits = model(images)
        loss = criterion(logits, labels)

        val_loss_total += loss.item() * images.size(0)

        predictions = logits.argmax(dim=1)
        correct += (predictions == labels).sum().item()
        total += labels.size(0)

val_loss = val_loss_total / total
val_accuracy = correct / total

print(f"Validation loss: {val_loss:.4f}")
print(f"Validation accuracy: {val_accuracy:.4f}")

This example assumes val_loader, device, criterion, and model have already been defined.

14.3 Why use both eval() and no_grad()?

  • model.eval() changes the behaviour of layers such as dropout and batch normalization where applicable.
  • torch.no_grad() disables gradient tracking in the enclosed operations, reducing memory use and computation.

Calling only one of these does not automatically perform the role of the other.

14.4 Training and validation patterns

Training lossValidation lossPossible interpretation
HighHighThe model may be underfitting, not trained enough, or poorly configured.
DecreasingDecreasingThe model may be learning useful patterns that generalize.
DecreasingIncreasingThe model may be overfitting.
LowLowThe model fits the training data and performs well on the validation data.

These are common patterns, not infallible rules. The interpretation depends on the task, data distribution, metric, and experimental setup.

14.5 Model selection

A common approach is to monitor validation loss after each epoch and retain the model with the best validation performance. This avoids assuming that the final epoch is always the best one. 

best_val_loss = float("inf")
best_state = None

# After computing val_loss for an epoch:
if val_loss < best_val_loss:
    best_val_loss = val_loss
    best_state = {
        name: tensor.detach().cpu().clone()
        for name, tensor in model.state_dict().items()
    }

# After training:
if best_state is not None:
    model.load_state_dict(best_state)

This example keeps the best model state in memory. It can be saved to disk as well if the workflow requires a persistent checkpoint.

15. Fashion MNIST model training and evaluation

15.1 What should be monitored?

A training run may track loss and accuracy for both the training and validation sets. Loss provides a measure used for optimization, while accuracy measures the fraction of examples classified correctly.

Two models with the same accuracy can have different losses because loss functions also reflect how confidently the model makes its predictions.

15.2 Save a trained model

A common PyTorch approach is to save the model's state dictionary, which contains its learned parameters. 

torch.save(model.state_dict(), "fashion_mlp.pth")

To reload the parameters, create the same architecture and load the saved state: 

model = FashionMLP()
model.load_state_dict(
    torch.load("fashion_mlp.pth", map_location=device)
)
model.to(device)
model.eval()

The architecture must match the saved parameter shapes. A state dictionary stores parameter values; it does not by itself describe every detail of the model's architecture or training history.

15.3 Reproducibility

Neural network training may involve randomized weight initialization, shuffled data, and other random operations. Fixing random seeds can help make experiments more reproducible. 

import random
import numpy as np
import torch

seed = 42

random.seed(seed)
np.random.seed(seed)
torch.manual_seed(seed)

if torch.cuda.is_available():
    torch.cuda.manual_seed_all(seed)

A fixed seed helps control randomness but does not guarantee bit-for-bit identical results across all devices, library versions, or computational operations.

15.5 Complete conceptual pipeline

The entire Fashion MNIST process can be summarized as:

  1. Load and preprocess images.
  2. Create data loaders.
  3. Define the MLP.
  4. Choose a loss function and optimizer.
  5. Train over multiple epochs.
  6. Validate without updating parameters.

  8. Save the model if needed.
  9. Evaluate on a separate test set when the model-selection process is complete.
